# 柜量管家 Android 项目（MVP 0.1.0）

## 当前包含
- Android 原生 Kotlin 项目，minSdk 26，targetSdk 35
- 使用 ML Kit 中文文字识别（本地设备端 OCR）
- 扫描系统相册中最近 5 个月的图片；优先使用媒体拍摄时间，缺失时使用媒体库加入时间
- 提取 ISO 集装箱号格式（4 位字母 + 7 位数字）
- 尝试识别装吉、装重、卸吉、卸重、作业单号、SO 号和订单日期
- SQLite 本地记录、月度/今日数量和每日匹配记录

## 用 Android Studio 编译 APK
1. Windows 安装 Android Studio（建议最新版）和 Android SDK Platform 35。
2. 解压项目，Android Studio 选择 Open，打开 `GuiLiangGuanJia` 文件夹。
3. 等待 Gradle Sync 完成。
4. Build > Build Bundle(s) / APK(s) > Build APK(s)。
5. APK 输出路径：`app/build/outputs/apk/debug/app-debug.apk`。

## 当前 MVP 的已知限制（测试前不可当作正式工资依据）
- 这是首个可运行开发骨架，尚未在真实小米 K80 上编译和验证。
- OCR 字段提取目前使用通用关键词规则；需要用更多真实订单样本校准，避免把普通号码误判为作业单号或 SO。
- 订单日期缺失时暂以图片时间作为临时日期，界面记录应人工核对；后续版本应改为“待确认”，不直接归入月份。
- 当前数据库的唯一约束以作业单号+SO号为主；若其中一个字段缺失，需在下一版完善去重策略。不同订单但柜号相同的场景也需要更多样本确认。
- Android 13+ 用户可能只授权部分照片；要扫描完整相册需授予完整照片访问权限。
- 后台持续扫描不是无限制常驻服务；当前通过用户点击触发扫描。后续可增加 WorkManager 定期增量扫描。
- 最近五个月过滤依赖 Android 媒体库提供的拍摄/加入时间。若图片被重新导入且原始拍摄时间元数据丢失，系统无法可靠还原真实拍摄时间。
